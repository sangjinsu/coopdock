# Go 협동 룸 서버 — 기능별 설계 문서

이 문서는 **1~6명이 함께 이동하고 협동하는 게임 서버**를 기능별로 풀어 설명합니다.
게임을 만드는 사람과 운영하는 사람이 같은 규칙을 이해하는 것이 목적입니다.

이 문서는 **목표 설계**이며 실제 구현 범위와 구분합니다. 현재 구현 범위·실행 방법·검증은 [서버 README](../../README.md)를 참조하세요.
reference 3D 이동 GameHandler와 서버 동기화의 현재 범위·검증은 서버 README를 참조하세요. 게임별 지형·충돌·협동 규칙, Godot 클라이언트, 운영 대시보드와 운영 부하·성능 측정은 후속 범위입니다.
각 문서의 상황 예시는 설계 동작을 설명하며, 실제 실행 결과 보고가 아닙니다.

## 문서에서 사용하는 구분

| 표시 | 뜻 |
|---|---|
| 확정 요구사항 | Go 우선, 룸당 1~6명 실시간 협동, 번호 입장·프라이빗 비밀번호, Godot 활용, 운영 대시보드 |
| 초기 설계 제안 | 구현을 시작할 때 따를 정책과 설정. 개발·측정 후 조정할 수 있음 |
| 후속 개발·미검증 | 아직 구현하거나 측정하지 않은 부분. 현재 제공되는 기능으로 읽지 않음 |

30Hz 계산, 15Hz 상태 전송, 운영 화면 2~5초 조회는 모두 **초기 제안**입니다.
번호 6자리·기본 공개·비밀번호 길이 4~64 Unicode 문자도 초기 제안이며 번호 입장·프라이빗 비밀번호 확인은 확정 요구입니다.
룸당 1~6명이라는 요구와 실제 서버 전체 수용 인원은 별개입니다.

## 먼저 알아둘 정책

아래는 **초기 설계의 정책**입니다. 실제 구현 여부와 검증 범위는 [서버 README](../../README.md)에서 확인하세요.

- 서버가 실제 위치·충돌·승패를 결정합니다. 방장은 게임을 시작할 권한을 가집니다.
- 참가자는 번호로 들어갑니다. private는 생성자 비밀번호를 확인하고 현재 참가 중인 다음 판에는 재입력하지 않습니다.
- 한 연결의 세션은 한 룸에만 속합니다. 진행 중인 `PLAYING` 룸에는 새로 들어갈 수 없습니다.
- 자동 재접속 복원은 초기 범위에 없습니다. 새 guest 연결은 이전 게임으로 자동 복귀하지 않습니다.
- 룸과 게임 상태는 메모리에 두므로 서버 재시작 때 사라집니다.
- 운영 명령의 지속 기록과 메모리 게임 상태는 보관 방식이 다릅니다. 자세한 내용은 06에 있습니다.

## 자주 나오는 단어

| 단어 | 쉬운 뜻 |
|---|---|
| 세션 | 게임 연결 하나에 서버가 붙인 접속 신분 |
| 룸 | 함께 게임을 기다리고 플레이하는 방 |
| 룸 번호 | 사람이 입력하는 숫자 문자열. 고정 내부 room ID와 구분 |
| match | 룸에서 진행하는 게임 한 판 |
| tick | 서버가 게임 상태를 한 번 계산하는 단계 |
| snapshot | 그 시점의 게임 전체 상태를 담은 묶음 |
| ACK | 서버의 입력 처리 확인. 성공 ACK는 실제 적용을 마친 뒤 보냄 |
| audit | 운영자가 어떤 조작을 했고 결과가 무엇인지 남기는 기록 |
